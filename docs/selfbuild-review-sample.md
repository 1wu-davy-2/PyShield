## 2. 样本怎么生成

```powershell
python tools/selfbuild.py --stage-only --workdir <空的临时目录>
```

该命令执行：

1. 把 `pyshield/`、`gui/` 复制到 staging，排除 `runtime_template/`、字节码和构建密钥；
2. 用普通 PyShield 构建流程加密 27 个 Python 模块；
3. 校验所有业务模块都是 stub、许可证为格式 3 且不含 `build_key`；
4. 删除 `*.shield-secret.json`，只留下可交付的受保护目录。

样本里的 `_shield_runtime/` 是运行时源码，这是 `runtime_source=True` 的结果，目的是让 PyInstaller 能静态分析运行时包；最终 onefile exe 中该目录由 PyInstaller 编译进 PYZ，不作为明文 `datas` 交付。

## 3. 已经验证的检查项

- 27 个业务模块（`pyshield/*.py`、`gui/*.py`、`manage.py`）全部以 stub 开头，原始函数体不在文件里；
- 样例 `pyshield/builder.py` 只有 `_pyshield_load_module(...)` 和 Base85 密文；
- 目录中不存在 `*.shield-secret.json`、`runtime_template/`、`__pycache__`、`.pyc`；
- 许可证解包后 `format == 3`，字段中没有 `build_key`；模块密钥由 `HKDF(master_key, salt="pyshield-build-key-v1", info=build_id)` 本地派生；
- 受保护模块可以在独立子进程中导入（`from pyshield import builder`）；
- 用同一份受保护源码打出的自保护 exe 可以启动并显示窗口（本地已做 20 秒存活与窗口标题检查）。

受保护模块的样子（`pyshield/builder.py` 开头，密文已截断）：

```python
# PyShield protected module. Generated by pyshield; do not edit.

from _shield_runtime import load_module as _pyshield_load_module

_pyshield_load_module(
    __name__,
    __file__,
    (
        "P*Yej0Rs#Waq4<b@q3VH6DTkw+vcIvAD}b$>Vdw3%C%USmG)Z={+fe!w_;)67P..."
        # 其余为 Base85 密文
    ),
)
```

许可证解包后的字段为 `bind_mode`、`build_id`、`cipher`、`created`、`customer`、`expires`、`fingerprints`、`format`、`grace_days`、`not_before`、`python`、`signature`；`format` 为 3，**没有 `build_key`**。

## 4. 建议审查的关注点

1. **不要用“源码不落地”作为结论。** 离线 exe 必须携带 master key 和自用许可证，具备调试能力的攻击者仍然可以在运行时取得明文；本方案的目标是提高静态逆向成本。
2. 检查 `_shield_runtime/_core.py` 中的密钥链：master key → HKDF → 模块密钥，以及许可证只承载授权数据、不承载 `build_key` 的改动。
3. 检查 `pyshield.lic` 的格式 3 解包结果与签名校验路径。
4. 检查 `runtime_source=True` 的适用范围：它只用于本自保护 PoC 的 PyInstaller 静态分析，不是默认发布选项；普通产品构建默认使用 `pyc` 运行时。
5. 检查样本与正式 exe 的密钥隔离：样本的 master key 只出现在样本的 `_core.py` 中，不能解密 `ci-develop-latest` 的 exe。
6. 继续保留原有审计中的残余风险：运行时内存明文、删除双份绑定/时钟锚点后重置、客户端许可证校验、exe 未签名、无 TPM/服务端解锁。

## 5. 与正式构建的关系

- `PyShieldBuilder.exe` 仍由正式 `PyShieldBuilder.spec` 构建，运行时源码已改为嵌入式 bundle，不再作为明文 `datas` 交付；
- `PyShieldBuilder-selfbuild.exe` 是实验产物，走 `tools/selfbuild.py` 和 `PyShieldBuilder.selfbuild.spec`，不替换正式发布链路；
- 自保护 exe 关闭了 manifest 完整性校验（`integrity="off"`），因为 onefile 的 `_MEIPASS` 布局与默认清单扫描不一致；发布完整性需要后续补 Authenticode。

完整的加固项与残余风险见 [security-hardening.md](security-hardening.md)；自保护 PoC 的实现说明见 [selfbuild-poc.md](selfbuild-poc.md)。
